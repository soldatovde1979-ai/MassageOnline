## Часть 2. Подробно

Команды — Windows, PowerShell. В начале каждого блока — `$ErrorActionPreference = 'Stop'`: при первой ошибке блок остановится, а не пойдёт дальше.

### 15.2.1. Тесты перед заливкой

```powershell
$ErrorActionPreference = 'Stop'
cd путь\до\massage-booking\tests
npm install          # один раз: ставит jsdom для тестов
node run-all.js
```

Ожидается 4 строки «Итог: … 0 FAIL» и «Все тесты прошли». Если есть «УПАЛ» — `clasp push` не делать, прислать вывод.

### 15.2.2. Заливка сервера

```powershell
$ErrorActionPreference = 'Stop'
cd путь\до\massage-booking
clasp push
```

Потом в редакторе: «Развернуть» → «Управление развёртываниями» → карандаш у текущего → «Версия: Новая» → «Развернуть». **Новое развёртывание не создавать** — сменится `exec`-URL, и разосланные ссылки перестанут работать.

Что уедет на сервер: новые `52_AdminBookings.gs`, `52_Portal.gs` и обновлённые `20_Availability.gs`, `32_Outbox.gs`, `41_TelegramAdapter.gs`, `53_Router.gs`, `62_SelfTests.gs`, `ui/admin*.html`. Папки `tests/` и `web/` лежат вне `src/` и в Apps Script не попадают.

### 15.2.3–15.2.5. Настройки сервера

1. В редакторе выбрать функцию `setupPortal` → «Выполнить». В журнале: «Добавлены ключи config: …». Повторный запуск безопасен — ничего не перезапишет.
2. В таблице `MassageBookingDB`, лист `config`, заполнить строки визитки. Пустые поля витрина просто не показывает.
   - `studio_after_booking` — код домофона, этаж. Виден только на экране «Запись подтверждена» и в «Моих записях».
   - `client_address_form` — `vy` (на «вы») или `ty` (на «ты»).
3. Там же проверить `web_app_url` — это `exec`-URL. Если пусто, выполнить `setWebAppUrl("<exec-URL>")`.

### 15.2.6. Проверка API

```powershell
$ErrorActionPreference = 'Stop'
$url  = 'https://script.google.com/macros/s/ВАШ_ID/exec'
$body = '{"action":"public.info","request_id":"ps-check-1","auth":{},"payload":{}}'
$r = Invoke-RestMethod -Uri $url -Method Post -ContentType 'text/plain;charset=utf-8' -Body $body
$r.ok                       # True
$r.data.min_slots           # 2
$r.data.horizon_days        # 30
```

Если вместо ответа пришла HTML-страница входа — у развёртывания не стоит «Доступ: Все» (шаг 10.2).

### 15.2.7. Выкладка на GitHub Pages (через браузер, без git)

1. github.com → «New repository» → имя `massage` → **Public** → «Create repository».
2. На странице репозитория — ссылка «uploading an existing file». Перетащить **содержимое** папки `web/`: `index.html`, `config.js`, `app_v1.css`, `app_v1.js`, `demo_v1.js`, `sw.js`, `manifest.webmanifest` и папку `icons` целиком → «Commit changes».
3. «Settings» → «Pages» → Source: «Deploy from a branch» → Branch: `main`, папка `/ (root)` → «Save».
4. Через 1–2 минуты сайт откроется по адресу `https://<ваш-логин>.github.io/massage/`. Сначала он работает в демо-режиме — так и должно быть.

> Секретов в `web/` нет: `exec`-URL и так вызывает браузер каждого клиента, публичный репозиторий ничего не раскрывает. Токены бота и секреты подписи живут только в Script Properties.

Вариант для командной строки (если git установлен):

```powershell
$ErrorActionPreference = 'Stop'
cd путь\до\massage-booking\web
git init
git add .
git commit -m "Витрина 1.1"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/massage.git
git push -u origin main
```

### 15.2.8. Боевой режим

На GitHub открыть `config.js` → карандаш «Edit» → строку `API_URL: 'demo'` заменить на `API_URL: 'https://script.google.com/macros/s/ВАШ_ID/exec'` → «Commit changes». Через минуту витрина работает с настоящим расписанием: демо-плашка пропадёт.

Хочется оставить демо для показа — выложить папку ещё раз во второй репозиторий, например `massage-demo`, и там `config.js` не трогать.

### 15.2.9. Проверка с телефона (тестовый календарь из 0.2)

- [ ] Открыть адрес витрины → видна лента дат, выбран первый день со свободным временем.
- [ ] Тап по началу выделяет 1 ч, тап по последнему слоту — растягивает; слот за «занято» — сообщение об ошибке.
- [ ] Записаться → «Запись подтверждена», код домофона виден, в тестовом календаре через минуту появилось событие `[МАССАЖ]`.
- [ ] «Мои записи» → «Перенести» на другой день → в календаре событие переехало.
- [ ] «Отменить» → запись отменена, время в ленте снова свободно.
- [ ] Закрыть и открыть витрину → «Здравствуйте, <имя>», при записи имя и телефон не спрашиваются.

### 15.2.10. Мастеру

- Android, Chrome: меню ⋮ → «Установить приложение» (или кнопка на вкладке «О мастере»).
- iPhone, Safari: «Поделиться» → «На экран „Домой“».

Витрина открывается без адресной строки, как приложение. Офлайн показывает последнее сохранённое.

### 15.2.11. Кнопка в боте (этап 13)

`@BotFather` → `/mybots` → `MariaMassage_bot` → «Bot Settings» → «Menu Button» → прислать адрес витрины, название кнопки — «Записаться». В чате с ботом слева от поля ввода появится кнопка; витрина откроется внутри Telegram в его теме.

Чтобы сервер доверял подписи Telegram (узнавал клиента по Telegram), нужны `notify_telegram_enabled = TRUE` и токен бота в Script Properties — это этап 13. До этого витрина в Telegram работает как обычный сайт.

## Обновление витрины в будущем

1. Поменялись файлы с тем же мажором (`app_v1.js` 1.1 → 1.2): загрузить их поверх в репозиторий. `sw.js` берёт свежие файлы из сети, кэш нужен только офлайн.
2. Новый мажор (`app_v2.js`): загрузить все файлы `web/` вместе — `index.html`, `config.js` и `app_v2.js` обязаны совпадать по мажору, иначе витрина покажет «Обновите файлы сайта целиком». В `sw.js` поправить список `SHELL` и поднять `CACHE`.
