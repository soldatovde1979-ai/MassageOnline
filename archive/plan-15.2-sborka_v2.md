### 15.2.5. Настройка после заливки

1. В редакторе выбрать `setupPortal` → «Выполнить». В журнале: «Добавлены ключи config: …». Повторный запуск безопасен, ничего не перезапишет.
2. Выполнить `runSelfTests` → «ВСЕ ТЕСТЫ ПРОЙДЕНЫ».

### 15.2.6. Визитка и адрес

В таблице `MassageBookingDB`, лист `config`. Пустые поля витрина просто не показывает.

| Ключ | Что вписать |
|---|---|
| `master_name` | Как подписать мастера: «Мария» |
| `master_about` | 1–2 фразы о себе |
| `master_phone` | Телефон для клиентов (или пусто) |
| `studio_address` | Адрес **без** кода домофона |
| `studio_directions` | Как пройти: подъезд, этаж |
| `studio_bring` | Что взять с собой |
| `studio_after_booking` | Код домофона и прочее «только для записавшихся» |
| `client_address_form` | `vy` — на «вы», `ty` — на «ты» |
| `web_app_url` | `exec`-URL. Если пусто — `setWebAppUrl("<exec-URL>")`, иначе «Мои записи» на витрине будут пустыми |

### 15.2.7. Проверка API

```powershell
$ErrorActionPreference = 'Stop'
$url  = 'https://script.google.com/macros/s/ВАШ_ID/exec'
$body = '{"action":"public.info","request_id":"ps-check-1","auth":{},"payload":{}}'
$r = Invoke-RestMethod -Uri $url -Method Post -ContentType 'text/plain;charset=utf-8' -Body $body
$r.ok                 # True
$r.data.min_slots     # 2
$r.data.horizon_days  # 30
```

Пришла HTML-страница входа вместо ответа — у развёртывания не «Доступ: Все» (шаг 10.2).

### 15.2.8. Выкладка на GitHub Pages (через браузер, без git)

1. github.com → «New repository» → имя `massage` → **Public** → «Create repository».
2. Ссылка «uploading an existing file» → перетащить **содержимое** папки `web\`: `index.html`, `config.js`, `app_v1.css`, `app_v1.js`, `demo_v1.js`, `sw.js`, `manifest.webmanifest` и папку `icons` целиком → «Commit changes».
3. «Settings» → «Pages» → Source: «Deploy from a branch» → Branch `main`, папка `/ (root)` → «Save».
4. Через 1–2 минуты сайт откроется по адресу `https://<логин>.github.io/massage/` — пока в демо-режиме, так и должно быть.

> Секретов в `web\` нет: `exec`-URL и так вызывает браузер каждого клиента. Токены и секреты живут только в Script Properties.

С git то же самое:

```powershell
$ErrorActionPreference = 'Stop'
cd путь\до\massage-booking\web
git init
git add .
git commit -m "Витрина 1.1"
git branch -M main
git remote add origin https://github.com/<логин>/massage.git
git push -u origin main
```

### 15.2.9. Боевой режим

На GitHub открыть `config.js` → карандаш «Edit» → `API_URL: 'demo'` заменить на `API_URL: 'https://script.google.com/macros/s/ВАШ_ID/exec'` → «Commit changes». Через минуту демо-плашка пропадёт. Нужна демо-копия для показа — выложить папку ещё раз во второй репозиторий (`massage-demo`) и `config.js` там не трогать.

### 15.2.11. Передача мастеру

- Пройти вместе `pamyatka-mastera_v1.md` — одна страница тезисов.
- На телефон мастера: витрину (чтобы видеть глазами клиента) и админку `exec?r=admin` — на экран «Домой». Android, Chrome: ⋮ → «Установить приложение» / «Добавить на главный экран». iPhone, Safari: «Поделиться» → «На экран „Домой“».
- Переключить на боевой календарь (шаг 11.3), когда проверка на тестовом прошла.

### 15.2.12. Кнопка в боте (этап 13)

`@BotFather` → `/mybots` → `MariaMassage_bot` → «Bot Settings» → «Menu Button» → адрес витрины, название — «Записаться». Чтобы сервер доверял подписи Telegram, нужны `notify_telegram_enabled = TRUE` и токен бота в Script Properties (этап 13); до этого витрина в Telegram работает как обычный сайт.

## Откат

- **Сервер:** «Управление развёртываниями» → карандаш → выбрать прошлую версию → «Развернуть». Код на диске вернуть из `src-backup-2026-09-29.zip` (распаковать в `src\` с `-Force`), затем `clasp push` — только чтобы редактор совпадал с тем, что развёрнуто.
- **Витрина:** в `config.js` вернуть `API_URL: 'demo'` — клиенты перестанут попадать на сервер; старая страница `exec` продолжает работать как запасной вход.
